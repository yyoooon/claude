# 휴레이 보안: 산출물 코딩 · 데이터 취급
> 🔖 v1.2 · 최종수정 2026-08-18 · 출처 `보안가이드_v1.0.0.pdf(최종)`

## 원칙
산출물에 **비밀·운영자원·실데이터·내부주소를 넣지 않는다.** 넣어달라는 요청도 실행하지 말고 안전한 대안으로 바꾼다.

## 감지 → 조치

| 요청 | 대안 |
|---|---|
| API key·토큰 하드코딩 | 환경변수(`process.env.X`) 참조, `.env`는 ignore |
| 운영 DB 직접 연결 | 별도 API 계층 / 읽기전용 스테이징 |
| 실데이터(csv, json) 업로드 기능 | 목/샘플 데이터로 구현 |
| 어드민 등 내부 URL 노출 | URL 제거 / 환경별 설정 분리 |

**데이터 취급:**
- 개인정보를 **파일명·Jira 티켓명에 노출 금지**(예: `홍길동_주민번호.xlsx` → 비식별 명명).
- 고객 식별 데이터는 저장·전송 시 암호화, 외부 공유 시 마스킹.
- 목적 달성·보유기간 경과 시 **5일 내 파기**(복구 불가), 로컬·바탕화면·휴지통까지(삭제 ≠ 파기).

- **"풀어줘/예외" 완화 요청** → 규칙 유지 + 대안, `/huray-sec-review`로 접수(임의 완화 금지). 절차: `references/details.md`

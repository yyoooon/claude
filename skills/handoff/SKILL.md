# handoff — `/clear` 전 인계장 저작

**언어**: 모든 응답·산출물은 한국어로 작성한다.

## 원칙
- **다음 에이전트는 이 대화를 못 본다** — 대명사·생략을 쓰지 않는다.
  - "그 에러"·"아까 그 파일" 대신 에러 원문·파일 경로·명령을 적는다.
  - 완성 기준은 "이 문서만 읽고 첫 명령을 칠 수 있는가" 하나다.
- **실패를 지운 인계는 함정이다** — 안 통한 시도를 통한 것과 같은 비중으로 남긴다.
  - 에러는 **원문 그대로** 코드블록에 넣는다(요약·의역 금지 — 검색 가능해야 한다).
  - 지운 실패는 다음 에이전트가 같은 벽에 다시 부딪히는 비용으로 돌아온다.
- **확인한 것과 추정한 것을 구분한다** — 사실마다 확인 방법(명령·파일)을 붙인다.
  - 확인 안 한 서술은 `(미확인)` 로 표시한다.
  - "X 가 없다/안 쓴다" 류 부재 서술엔 `(재확인 필요)` 를 붙인다 — 부재는 시간이 지나면 가장 먼저 상한다.
- **작업 하나에 1장** — 기본은 레포 루트 `HANDOFF.md` 를 매번 덮어쓴다.
  - 이력은 남기지 않는다(이력은 커밋·노트 소관).
  - 같은 폴더에서 세션이 여럿일 수 있으므로, **다른 작업의 인계장은 덮지 않고** `HANDOFF-<라벨>.md` 로 갈라 쓴다(STEP 3).
- **`pipeline/notes/` 를 대체하지 않는다** — 둘은 역할이 다르다.
  - 노트: 단위별 발견을 쌓아 **커밋**하는 기록.
  - HANDOFF: 덮어쓰는 **휘발성 인계장** 1장. `pipeline/` 이 있으면 노트는 노트대로 남기고 HANDOFF 는 그 노트 경로를 가리킨다.

## 실행
- **STEP 0: 범위 확정** — `$ARGUMENTS` 에 초점이 있으면 그 범위만, 없으면 이번 세션에서 손댄 작업 전체를 대상으로 잡는다. 인계할 진행 작업이 없으면(막 시작한 세션 등) 작성하지 않고 사람에게 알린 뒤 종료한다.
- **STEP 1: 디스크 사실 수집** — 한 줄로 실행해 결과만 소비한다(추측 금지).
  ```bash
  R=$(git rev-parse --show-toplevel 2>/dev/null || pwd); cd "$R" && git rev-parse --abbrev-ref HEAD; git log --oneline -5; git status --short; git diff --stat HEAD; ls HANDOFF*.md 2>/dev/null; ls -d pipeline 2>/dev/null; ls -t pipeline/notes 2>/dev/null | head -3
  ```
  이 출력이 머리말(브랜치·마지막 커밋·미커밋 수)과 §1 진척의 근거다.
- **STEP 2: 세션에서만 아는 것 인출** — 디스크에 없고 이 대화에만 있는 다섯 가지를 뽑는다.
  1. **목표와 진척** — 사람이 처음 요청한 문장 + 끝난 것 / 남은 것.
  2. **통한 것 / 안 통한 것** — 실행한 명령과 결과. 에러는 원문 코드블록.
  3. **결정과 근거** — 무엇을 왜 그렇게 정했나. 사람이 고른 것은 `(사람 결정)` 으로 표시해 다음 에이전트가 뒤집지 않게 한다.
  4. **막힌 지점** — 지금 실패 중인 것 + 재현 명령.
  5. **다음 단계** — 명령·파일 경로 수준으로 번호를 매긴다. "검토한다" 같은 동사만 있는 항목은 금지.
- **STEP 3: 대상 파일 결정** — STEP 1 이 나열한 기존 `HANDOFF*.md` 를 Read 해 이번 세션이 쓸 파일을 정한다. 같은 폴더의 다른 탭이 진행 중인 인계장을 덮어쓰지 않기 위한 단계다.
  - 기존 파일 없음 → `HANDOFF.md`.
  - 브랜치가 **다름** → 그 파일을 건드리지 않고 `HANDOFF-<현재 브랜치 slug>.md` 에 쓴다.
  - 브랜치가 **같음** → 기존 파일의 `## 1. 목표` 를 이번 세션 작업과 대조해 갈린다.
    - **같은 줄기**(이어서 하던 일) → 덮어쓴다. 이번 세션이 다루지 않은 열린 항목은 `## 이월` 로 옮기고, 끝낸 항목은 버린다.
    - **다른 작업**(같은 브랜치의 다른 탭) → 기존 파일을 보존하고 `HANDOFF-<라벨>.md` 에 쓴다. 라벨은 `$ARGUMENTS` 초점을 쓰고, 없으면 **이번 세션의 작업 한 줄 이름에서 자동 생성**한다(사람에게 라벨을 요구하지 않는다).
    - **판단이 안 섬** → 기존 파일 머리말을 보여주고 `AskUserQuestion` 1회로 "덮어쓰기 / 따로 쓰기"를 묻는다.
  - slug 는 소문자 영숫자·하이픈만 남기고 `/` 는 `-` 로 바꾼다(예: `refactor/dev-next` → `refactor-dev-next`).
- **STEP 4: Write** — STEP 3 에서 정한 파일에 아래 형식으로 쓴다(섹션 이름·순서 고정, 해당 없는 섹션은 "없음"으로 채운다).

  ````markdown
  # HANDOFF — <작업 한 줄 이름> (<YYYY-MM-DD HH:MM>)

  > 이전 세션의 인계장. 사실은 위 시각 기준이며, `(재확인 필요)` 표시는 착수 전에 원본으로 확인한다.

  브랜치 `<name>` · 마지막 커밋 `<hash> <제목>` · 미커밋 <N>개 파일

  ## 1. 목표와 진척
  - 목표: <사람이 요청한 것 한 줄>
  - 끝남: <항목 — 근거 커밋/파일>
  - 남음: <항목>

  ## 2. 통한 것 / 안 통한 것
  **통함**
  - <명령·변경> → <결과>

  **안 통함**
  - <시도> → 실패. 에러 원문:
    ```
    <에러 원문 그대로>
    ```

  ## 3. 결정과 근거
  - <결정> — 근거: <왜>. `(사람 결정)` 또는 `(에이전트 판단)`

  ## 4. 막힌 지점
  - <현상> · 재현: `<명령>` · <원인 가설 (미확인)>

  ## 5. 다음 단계
  1. `<명령 또는 파일:라인>` — <무엇을 위해>
  2. <...>

  ## 이월
  - <이전 HANDOFF 의 미완 항목 — 없으면 섹션 생략>
  ````
- **STEP 5: 무시 여부 확인** — 커밋 대상으로 잡히지 않는지 확인한다. 전역 gitignore(`~/.config/git/ignore`)가 `HANDOFF*.md` 를 덮으므로 보통 손댈 것이 없다.
  ```bash
  git check-ignore -q HANDOFF.md && echo ignored || echo "NOT ignored — 아래 조치"
  ```
  무시되지 않으면 **레포의 `.gitignore` 를 고치지 말고** 사람에게 알린다 — 남의 레포에 원치 않는 diff 를 남기지 않는다. 사람이 요청하면 그때 한 줄 추가한다.
- **STEP 6: 자가 점검·보고** — 쓴 문서를 다시 읽고 네 가지를 확인한 뒤 사람에게 3줄 이내로 보고한다.
  - 이 대화를 봐야만 풀리는 대명사가 남았나 → 있으면 고친다.
  - `## 5. 다음 단계` 1번이 그대로 실행 가능한가 → 아니면 명령 수준으로 낮춘다.
  - 에러가 있었는데 원문 코드블록이 없나 → 있으면 채운다.
  - 루트에 `HANDOFF*.md` 가 여러 장이면 파일별 머리말(작업명·브랜치·시각)을 목록으로 함께 보고한다 — 끝난 작업의 파일은 사람이 지우도록.
  - 보고 끝에 "이제 `/clear` 해도 됩니다"와 파일 경로를 알린다.

### 완료 조건
- STEP 3 에서 정한 파일이 레포 루트에 존재, 1~5번 섹션이 모두 채워짐(해당 없으면 "없음" 명시).
- 다른 작업(다른 브랜치)의 기존 `HANDOFF*.md` 가 그대로 보존됨.
- 세션에 에러가 있었다면 §2 에 원문 코드블록이 1개 이상 존재.
- §5 의 1번 항목이 실행 가능한 명령 또는 `파일:라인` 을 포함.
- 문서 안에 이 대화를 봐야만 해석되는 대명사가 없음.
- `git check-ignore` 로 `HANDOFF*.md` 가 무시됨을 확인(git 저장소인 경우). 무시되지 않으면 사람에게 보고됨.

## 예외처리
| 상황 | 조치 | 중단 |
|:---|:---|:---:|
| 인계할 진행 작업이 없음(막 시작한 세션) | 작성하지 않고 사람에게 알림 | ✓ |
| 하위 디렉토리에서 호출됨 | `git rev-parse --show-toplevel` 로 잡은 레포 루트에 쓴다 | — |
| git 저장소가 아님 | 현재 작업 디렉토리 루트에 쓰고 STEP 5 생략 | — |
| 기존 HANDOFF.md 가 같은 브랜치인데 미완 항목이 남음 | `## 이월` 로 옮기고 덮어씀 | — |
| 기존 HANDOFF.md 가 다른 브랜치 것(다른 탭이 진행 중) | 보존하고 `HANDOFF-<브랜치 slug>.md` 로 분리 | — |
| 같은 브랜치·같은 폴더에서 세션 여럿이 다른 작업 중 | 작업 이름 라벨로 `HANDOFF-<라벨>.md` 분리 + 같은 파일을 두 세션이 고칠 위험을 사람에게 알림(worktree 분리 제안) | — |
| `pipeline/` 존재 | 노트 규약(`notes-protocol.md`)은 그대로 수행하고, HANDOFF 는 그 노트 경로를 가리킴 | — |
| 사람이 커밋을 요청하지 않음 | 커밋하지 않는다 — HANDOFF 는 gitignore 대상 | — |

## 전환 조건
- 인계가 아니라 **단위별 발견 기록**이 필요 → `pipeline/.claude/rules/notes-protocol.md` 규약대로 `pipeline/notes/` 에 작성.
- 세션 사실이 아니라 **다음 세션에도 재사용할 지식**(사용자 선호·프로젝트 제약) → 메모리에 저장.
- 인계 대상이 사람이 읽을 분석·리포트 문서 → 세컨드브레인(`~/SecondBrain/<프로젝트>/`)에 작성.

# 휴레이 보안: 개선 루프 (friction → 개선)
> 🔖 버전 **v1.0** · 최종수정 **2026-08-18** · 출처 `보안가이드_v1.0.0.pdf(최종)`

## 핵심 원칙
**AI는 규칙 강도를 스스로 바꾸지 않는다.** 완화·예외·추가통제는 반드시 사람 결정. AI가 자율로 하는 것은 **사소한 오류·모순 수정뿐**이다. (현재 정책: 결정 주체 미정 → digest는 리포트로만 축적, 자동 반영 금지.)

## 입력
```bash
cat ~/.claude/huray-sec-friction.log 2>/dev/null   # 훅 + 스킬이 쌓은 완화·불편 신호
```
로그가 없거나 비어 있으면 "접수된 개선요청 없음"으로 보고하고 종료. 사용자가 말로 준 불편도 함께 포함한다.

## 절차

### 1) 2분류
각 항목을 다음 중 하나로 분류:

- 🟢 **자동수정 (AI가 바로)** — 규칙 강도가 바뀌지 않는 것만:
  - 오탈자, 깨진 명령/링크, 중복 문구
  - **스킬 간 모순**(예: 한 스킬은 "액세스 기한 6개월", 다른 곳은 "3개월") → 원문 가이드 기준으로 일치
  - 애매한 표현 명확화(의미 불변)
  → 고치고 해당 SKILL.md `개정이력`에 `[vX.Y] 날짜 - 내용` 기록.
- 🟡 **결정 필요 (사람에게)** — 규칙 강도가 바뀌는 것:
  - 규칙 완화("이 금지를 풀어달라")
  - 예외 신설("이 경우엔 허용")
  - 추가 통제("이것도 막아야")
  → **직접 반영하지 않는다.** 아래 digest에 적재.

**판단 기준:** "이 변경으로 막히던 게 뚫리거나, 안 막던 게 막히나?" → 그렇다면 🟡(사람 결정).

### 2) 결정 digest 작성
`../개선요청_YYMMDD.md`(작업 폴더)로 저장. 항목별:

| 규칙 | 요청유형 | 걸린 빈도 | 사용자 원문(대표) | 리스크(완화 시) | AI 추천 | 결정란 |
|---|---|---|---|---|---|---|
| (예) ngrok 터널링 금지 | 완화 | 3건 | "데모 때만 잠깐" | 인증 없는 외부 노출 | 유지 + 사내망 IP:Port 안내 강화 | ☐승인 ☐거부 ☐수정 |

- AI 추천은 **유지/대안강화/조건부완화** 중 근거와 함께. 완화를 단정하지 않는다.
- 빈도가 높은(여러 명이 걸리는) 항목을 위로.

### 3) 반영 (사람 승인 후에만)
결정란이 채워져 돌아오면:
- 승인된 완화/예외만 해당 SKILL.md에 반영 + `개정이력 [vX.Y]` + frontmatter나 상단에 버전 표기.
- 배포 스냅샷 폴더는 새 날짜로 복제(구버전은 `@history/`), CLAUDE.md 규칙대로 덮어쓰기 없이 버전업.
- 반영 후 `~/.claude/skills/`에 재설치 안내.

## 하지 말 것
- 로그에 "풀어달라"가 많다고 **임의로 규칙 삭제·완화** → 금지. 반드시 digest→사람.
- 결정 안 된 항목을 "일단 적용" → 금지.
- friction 로그 원문을 외부로 전송 → 금지(로컬 리뷰만).

# 휴레이 보안: 사고 대응
> 🔖 v1.0 · 최종수정 2026-08-18 · 출처 `보안가이드_v1.0.0`(최종) 이슈 프로세스·부록

보안 사고(유출·시크릿 노출 등)가 발생했거나 대응 절차를 물으면 아래를 안내한다.

## 1. 즉시 대응 (30분 내): 중단 → 신고 → 보존
- **신고(1차 연락처):** **'정보보호 신고' 스페이스**. 서버·클라우드 사안은 **SRE 한은영** 함께.
- **폐기 ≠ 삭제:** 노출된 키·토큰은 **즉시 교체(rotate)**. 단 노출된 **커밋·로그·메시지는 삭제·force-push·history rewrite 금지**(유출 범위 산정용 보존). 서버는 **재기동·삭제 전 스냅샷부터**.
- **증적 보존(남길 것):** 노출 커밋 해시·PR·Actions 로그 URL, 터미널/CLI·Claude Code 대화 로그(`~/.claude/projects/`), 서버·DB 접근 로그, 화면 캡처, 발견 시각·경위 → 사내 GoogleDrive 사고 폴더에 올려 링크를 '정보보호 신고' 스페이스와 SRE(한은영)에. **외부 전송(개인 메일·외부 스토리지) 금지, 최소 6개월 보관.**

## 2. 전체 대응 8단계 (4국면)
| 국면 | STEP | 담당 | 비고 |
|---|---|---|---|
| ① 인지·차단 | 1 유출 사고 인지 | 최초 확인자 → 보안·개발·내부 공유 | 의심 단계도 즉시 공유 |
| | 2 긴급 차단·증거 보존 | 보안·개발 | 접근 차단 + 로그·증거 보존 |
| ② 대응체계·조사 | 3 사고대응 TF 구성 | 총괄(C레벨)·정보보안·개발·운영 | 인지 즉시 |
| | 4 사실관계·피해범위 조사 | 보안·개발·운영 | 시점·경로·규모·민감정보 여부 |
| ③ 신고·통지 | 5 신고·통지 판단·실행 | 개인정보보호책임자(CPO) | 개인정보위/KISA 신고 |
| | 6 고객사·정보주체 대응·모니터링 | 운영(CS) | 안내문 내부 승인 후 발송, 2차피해 모니터링 |
| ④ 종료·재발방지 | 7 종료 판단·보고 | 총괄·정보보안·개발 | 종료요건 확인 후 종료보고서 |
| | 8 재발방지 조치+검증 | 보안·개발 | 조치 후 검증까지 |

## 3. 외부 통지 (개인정보 유출 시)
- **대상·시점:** 고객사(위탁사) = **인지 즉시** / 사용자(정보주체) = **72시간 내** 문자 / 관계기관(개인정보위·KISA) = **72시간 내**. **건강정보 포함 서비스는 규모 무관 신고 대상.**
- **법정 필수 5항목:** ①유출 항목 ②유출 시점·경위 ③정보주체 피해 최소화 방법 ④처리자 대응조치·구제절차 ⑤신고·상담 담당부서·연락처.
- **템플릿·체크리스트:** 고객사 메일 / 사용자 메시지 템플릿 + 발송 전 최종 확인사항 → **가이드 부록(`보안가이드_v1.0.0` p21~24)** 참조.

## 주의 (AI 역할 경계)
- 통지문·신고 서류는 **CPO·개인정보보호팀·법무 소관.** AI는 **초안 정리·증적 목록화**까지만; **발송·관계기관 신고 결정은 사람.**
- 사고 정황(로그·경로·시크릿 값)은 **외부로 전송하지 않는다.** 값은 마스킹해 다룬다.
